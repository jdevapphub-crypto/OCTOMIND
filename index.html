🚀 App Launch & Store Guide

Google Play Apple App Store Huawei AppGallery

▶️ Google Play Store

Requirements for a new app:

  • Google Play Developer account: $25 once
  • App must target recent Android API (currently API 34+)
  • Signed APK or AAB (Android App Bundle)
  • Privacy Policy URL (required if app collects data)
  • Content rating questionnaire
  • App category & contact details
  • Data safety form
  • Store listing: title, short & full description, screenshots, feature graphic, icon (512×512)
  • App must not violate impersonation, hate, or malware policies

Useful links:
Google Play Console
Play Console Help

🍎 Apple App Store

Requirements for a new app:

  • Apple Developer Program: $99/year
  • Build with Xcode, upload via App Store Connect
  • App must follow App Store Review Guidelines
  • Privacy Policy URL required
  • App Privacy details (data collection)
  • Age rating
  • Screenshots for iPhone, iPad (if supported), Apple Watch (if supported)
  • App icon (1024×1024 for App Store)
  • Support URL & marketing URL (optional but recommended)

Useful links:
App Store Connect
App Store Review Guidelines

🌸 Huawei AppGallery

Requirements for a new app:

  • Huawei Developer account (free)
  • Signed APK or App Bundle (Huawei supports APK & AAB)
  • Privacy Policy URL (mandatory)
  • App must comply with Huawei's content policies
  • App icon: 216×216 px (recommended)
  • Screenshots: at least 3, up to 8, various sizes accepted
  • Feature graphic: 1024×500 px
  • Category, age rating, contact info

Useful links:
Huawei AppGallery Connect
AppGallery Documentation

📦 General checklist for all stores

  • App name (unique, no trademark issues)
  • Short description (80 chars) & full description (4000 chars)
  • Privacy policy URL (hosted, publicly accessible)
  • App icon: high-resolution (512×512 PNG for Play, 1024×1024 for Apple)
  • Feature graphic (Play: 1024×500, AppGallery similar)
  • Screenshots (phone & tablet if applicable)
  • Promo video (optional)
  • Contact email & website
  • Content rating
  • Target audience & age group
  • Data safety / privacy declaration

📱 Google Play — Icon & Screenshots

  • App icon: 512×512 px, 32-bit PNG (with alpha), max 1MB
  • Feature graphic: 1024×500 px, JPEG or 24-bit PNG (no alpha)
  • Phone screenshots: 2–8 images, 16:9 or 9:16, min 320px, max 3840px
  • 7-inch tablet: 2–8 images, 16:9 or 9:16 (optional but recommended)
  • 10-inch tablet: 2–8 images (optional)
  • Promo video: YouTube URL (optional)

Tips: Show the core UI, highlight features with text overlays, keep it clean.

🍎 Apple App Store — Icon & Screenshots

  • App icon: 1024×1024 px, PNG, no transparency, no rounded corners
  • iPhone screenshots: 6.7" (1290×2796), 6.5" (1242×2688), 5.5" (1242×2208) — at least one set
  • iPad screenshots: 12.9" (2048×2732), 11" (1668×2388) — if app supports iPad
  • App previews: optional 15–30 sec videos

Tips: Use device frames, show real UI, add short captions.

🌸 Huawei AppGallery — Icon & Screenshots

  • App icon: 216×216 px, PNG
  • Feature graphic: 1024×500 px
  • Screenshots: 3–8 images, recommended 1080×1920 or similar
  • Promo video: optional

Tips: Similar to Play Store, but ensure Chinese market guidelines if targeting China.

🖼️ Quick icon sizes summary

  • Google Play Store: 512×512
  • Apple App Store: 1024×1024
  • Huawei AppGallery: 216×216
  • In-app icons: multiple densities (mdpi, hdpi, xhdpi, etc.)

💰 App Pricing Models

  • Free: Ad-supported or feature-limited
  • Paid: One-time purchase (e.g., $0.99 – $9.99)
  • Freemium: Free with in-app purchases (IAP)
  • Subscription: Monthly/yearly (e.g., $2.99/month)
  • Pay-what-you-want: Donation-based

Store fees: Google 15–30%, Apple 15–30%, Huawei 15–30%.

📢 Types of Ads for Apps

  • Banner ads: Small, top/bottom – low revenue
  • Interstitial ads: Full-screen between actions
  • Rewarded video: User watches to get in-app reward
  • Native ads: Blend into UI
  • Playable ads: Interactive demo

🔗 Why you need a Privacy Policy URL

All major app stores require a publicly accessible URL to your privacy policy if your app collects any personal data (even analytics).

  • Google Play: mandatory if data collection
  • Apple: mandatory for all apps
  • Huawei: mandatory

🛠️ How to create a policy with Google Sites

  1. Go to sites.google.com
  2. Create a blank site.
  3. Name it e.g. "MyApp Privacy Policy".
  4. Add a new page.
  5. Paste your policy text.
  6. Publish the site.
  7. Copy the published URL.
  8. Use that URL in the store listing.

Tip: Also create a "Terms of Service" page and link it.

🧾 What to include in a Privacy Policy

  • What data you collect
  • How you collect it
  • Why you collect it
  • Who you share it with (third-party services)
  • How long you keep it
  • How users can request deletion
  • Contact information
  • Children's privacy (COPPA/GDPR-K)
  • Changes to policy

📝 How to draft a policy (step-by-step)

  1. Identify data: What personal data does your app collect? (email, name, location, device ID)
  2. Purpose: Why do you need it? (account, analytics, ads)
  3. Third parties: List all services (e.g., Firebase, AdMob, AWS).
  4. Retention: How long do you keep data?
  5. User rights: How can users access, correct, or delete their data?
  6. Children: Are you targeting under 13? If yes, COPPA applies.
  7. Security: How do you protect data? (encryption, HTTPS)
  8. Contact: Provide an email for privacy questions.
  9. Legal review: Consult a lawyer for full compliance (POPIA in South Africa).

⚖️ South African context (POPIA)

If you operate in South Africa, the Protection of Personal Information Act (POPIA) applies.

  • You must have a lawful basis for processing.
  • You must inform users what you collect and why.
  • Users have the right to access, correct, and delete their data.
  • You must secure data and report breaches.

📚 Learn HTML & Code Basics

FROM ZERO TO HERO
Master the fundamentals of web development. This room teaches you how HTML, CSS, and JavaScript work together — from a single button to a complete app structure.

🧱 1. The Basic HTML Structure

Every web page follows the same skeleton. Think of it like a human body:

<!DOCTYPE html>  <!-- Tells the browser: "This is HTML5" -->
<html lang="en">  <!-- The root container -->
  <head>  <!-- The brain: invisible info -->
    <meta charset="UTF-8">
    <title>My App</title>
    <style>... CSS goes here ...</style>
  </head>
  <body>  <!-- The body: visible content -->
    <h1>Hello World</h1>
    <button>Click Me</button>
  </body>
</html>

What goes in the <head>?

  • <meta> — character set, viewport, description
  • <title> — text on the browser tab
  • <style> — all your CSS (appearance)
  • <script> — JavaScript (behaviour)
  • <link> — external files (fonts, icons)

What goes in the <body>?

  • Headings, paragraphs, images, buttons
  • Divs, sections, forms, lists
  • Anything the user can see or interact with

🔘 2. Full Button Code (Anatomy)

A button has three layers: HTML (structure), CSS (appearance), and JavaScript (action).

HTML — the button element:

<button class="my-btn" onclick="doSomething()">
  Click Me
</button>

CSS — the appearance:

.my-btn {
  background: #27d9ff;
  color: #000;
  padding: 12px 24px;
  border: none;
  border-radius: 10px;
  font-weight: bold;
  cursor: pointer;
}

JavaScript — the action:

function doSomething() {
  alert("Button clicked!");
}

Where does each part go?

  • HTML button → inside <body>
  • CSS → inside <style> in <head> (or external .css file)
  • JavaScript → inside <script> before </body> (or external .js file)

🗂️ 3. Divs, Sections & Layout

Think of <div> as a box. You put things inside boxes and arrange them.

<div class="container">
  <header>Top bar</header>
  <main>
    <section class="hero">Welcome</section>
    <div class="grid">
      <div>Card 1</div>
      <div>Card 2</div>
    </div>
  </main>
  <footer>Bottom</footer>
</div>

Key CSS for layout:

.container {
  width: 90%;
  margin: 0 auto;  /* centers it */
}
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 16px;
}

🎨 4. Styling: Colors, Fonts, Spacing

CSS makes things look good. Here are the essentials:

body {
  background: #050810;      /* dark background */
  color: #ffffff;           /* white text */
  font-family: Arial, sans-serif;
}

h1 {
  font-size: 2rem;           /* 2x root size */
  margin-bottom: 16px;
}

.card {
  background: #0b1220;
  padding: 20px;
  border-radius: 12px;
  border: 1px solid rgba(255,255,255,0.1);
}

Spacing shortcut: padding = inside space, margin = outside space.

Colors: Use hex (#27d9ff), rgb (rgb(39,217,255)), or rgba for transparency.

🔄 5. JavaScript: Making Things Work

JavaScript is the brain of your page. It reacts to clicks, saves data, and changes the page.

// 1. Grab an element
const btn = document.getElementById("myBtn");

// 2. Listen for a click
btn.addEventListener("click", function() {
  alert("You clicked!");
});

// 3. Save data to localStorage
localStorage.setItem("name", "Jason");

// 4. Read data back
const name = localStorage.getItem("name");

Functions: A block of code you can run anytime.

function greet(name) {
  console.log("Hello " + name);
}
greet("Jason");  // Output: Hello Jason

🚀 6. Starting a New Screen

To create a new "screen" or page, you have two main options:

Option A — Separate HTML files:

  • Create index.html (home)
  • Create about.html (about page)
  • Link them: <a href="about.html">About</a>

Option B — One page, multiple sections (SPA style):

<div id="homeScreen">Home content</div>
<div id="aboutScreen" class="hidden">About content</div>

<script>
function showAbout() {
  document.getElementById("homeScreen").classList.add("hidden");
  document.getElementById("aboutScreen").classList.remove("hidden");
}
</script>

This is exactly how NINE: OCTOBRAIN switches between rooms!

📋 7. Full Checklist: New App From Scratch

  1. Create index.html with the basic structure (DOCTYPE, html, head, body).
  2. In <head>: Add charset, viewport, title, and <style> for CSS.
  3. In <body>: Add your header, main content, and footer.
  4. Add a button: <button onclick="myFunc()">Go</button>.
  5. Add <script> before </body> for your JavaScript.
  6. Style everything with CSS in the <style> tag.
  7. Test in browser: Open the file and click around.
  8. Save data with localStorage if you need persistence.
  9. Add more screens using hidden divs and classList toggles.
  10. Deploy: Upload to Google Sites, Netlify, or any web host.

💡 8. Pro Tips & Common Mistakes

✅ Do:

  • Always close your tags: <div>...</div>
  • Use class for styling, id for JavaScript hooks
  • Test on mobile — use @media queries
  • Keep functions small and focused
  • Comment your code: <!-- like this -->

❌ Avoid:

  • Forgetting charset="UTF-8" — breaks special characters
  • Using id for multiple elements — must be unique
  • Putting CSS in the body — keep it in <head>
  • Hardcoding API keys in frontend JavaScript
  • Not testing on different screen sizes

CSS variables: Use :root { --my-color: #27d9ff; } then color: var(--my-color); for easy theming.
